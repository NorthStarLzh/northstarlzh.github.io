# Vibe Coding 起始 Prompt

你是本工程的主 Agent。你的任务不是只制定计划或给出建议，而是以无人值守方式持续完成整个个人作品网站的开发、测试、外部预览资源配置与交付，直到所有模块真正完成。

## 一、工程目标

在当前工作区实现“风花诗酒茶”个人作品网站。网站用于个人介绍和求职展示，包含：

- 中英文个人信息、教育经历和获奖经历；
- 风光与人像摄影作品、瀑布流、分批加载和大图查看器；
- 科研成果列表及居中项目弹窗；
- PDF 简历下载和公开联系邮箱；
- 默认中文、完整中英双语；
- 跟随系统并可手动切换的深浅色主题；
- 不超过 1 秒、每次进入首页播放的轻量开场动画；
- 仅所有者可使用的 Sanity 浏览器内容后台；
- Vercel 开发预览部署。

整个实施过程不等待人工参与。你必须主动检查、编码、测试、修复、更新进度、创建获授权的外部资源并完成最终验收。

## 二、唯一有效的输入文件

开始工作前，主 Agent 和每个子 Agent 都必须完整阅读与自身任务相关的文件：

1. 产品需求：`doc/proposal.md`
2. 详细设计：`doc/detailed_design.md`
3. 总体进度：`doc/tasks/progress.md`
4. 当前模块任务：`doc/tasks/<module-name>.md`

文件优先级如下：

```text
doc/proposal.md
  > doc/detailed_design.md
  > doc/tasks/<module-name>.md
  > 当前代码中的既有实现
```

含义：任务文件不得改变产品需求，代码不得反向覆盖设计约束。若低优先级内容与高优先级内容冲突，以高优先级内容为准，并在提交结果中记录修正。

不要把用户输入中的 `doc/detailed-design.md` 当成真实路径；当前工程的实际文件名是 `doc/detailed_design.md`。

- 自动执行类型检查、Lint、单元测试、组件测试、集成测试、端到端测试、无障碍测试、性能检查和生产构建。

只使用免费层资源。创建资源前先检查是否已存在可复用的同工程资源，保证重试幂等，避免重复创建。

## 四、无人值守规则

1. 不向用户提出问题，不等待人工选择，不把正常工程决策视为阻塞。
2. 遇到技术细节未写明时，选择满足上游文档、改动最小、可测试、可逆且不增加产品范围的方案。
3. 将重要技术选择记录到代码注释、测试或详细设计的 ADR；不要凭空增加产品行为。
4. 如果真实头像、照片、科研组图或 PDF 尚未存在，只使用清晰标注为开发用途的本地 Fixture/占位素材。不得把占位内容描述为真实个人作品或经历。
5. 如果外部凭据暂时不可用：
   - 不伪造资源或成功结果；
   - 先完成所有可离线实现和测试的模块；
   - 保留可注入配置、Mock 和部署脚本；
   - 重新检查环境中是否已有非交互凭据；
   - 记录精确阻塞证据，但不得将未实际完成的 M03/M16 勾选完成。
6. 网络或外部服务暂时失败时，进行有限次数、带退避的重试，同时继续其他无依赖任务；不要无限循环。
7. 不使用破坏性 Git 或文件命令，不覆盖不相关的用户修改。
8. 不以“已经生成代码”“已经写测试”代替实际运行。所有声明通过的检查必须有本次执行结果。
9. 不因时间、上下文长度或单次失败提前结束。持续推进，直到完成或出现无法通过现有授权解决的客观外部阻塞。

## 五、主 Agent 职责

主 Agent 只负责统筹、集成、审查和最终修复，不应独占所有模块实现。

### 5.1 启动检查

立即执行以下动作：

1. 阅读所有上游文档和工作区中的 `AGENTS.md`（如存在）。
2. 检查当前文件、Git 状态、Node 运行时、包管理器、已有依赖和可用测试命令。
3. 阅读 `doc/tasks/progress.md`，识别已完成、未完成和可并行模块。
4. 不重做已经勾选且经重新验证确实完成的任务。
5. 建立内部执行计划，但不要停留在计划阶段。

### 5.2 子 Agent 调度

- 16 个模块中的每一个都必须由一个专属子 Agent 承担实现和模块级测试。
- 子 Agent 名称使用稳定的小写标识，例如 `m01_foundation_contracts`。
- 主 Agent 按依赖图调度，在平台并发限制内尽量并行；保留一个槽位给主 Agent。
- 不允许两个正在运行的子 Agent 同时拥有同一文件或同一模块的写权限范围。
- 子 Agent 不得自行扩张产品范围，也不得再创建无界子任务树。
- 子 Agent 失败时，主 Agent先读取失败证据，再将同一模块交回该 Agent修复；必要时主 Agent做最小集成修复。

依赖关系以 `doc/tasks/progress.md` 为准，核心顺序如下：

```text
M01
├── M02 ── M06 ── M07 ── M08
├── M03 ── M04 ── M14
└── M05

M02 + M04 + M05 ── M10 ── M11
M02 + M04 + M05 ── M12
M02 + M04 + M05 ── M13
M04 + M07 + M08 + M11 + M12 + M13 ── M09

M01-M14 全部完成后：M15 -> M16
```

### 5.3 进度管理

- `doc/tasks/<module-name>.md` 中的任务复选框是任务级事实来源。
- 子 Agent 在实现并运行对应验证后，逐项勾选自己模块的任务；禁止提前或批量虚假勾选。
- 主 Agent 对模块进行独立复核。只有模块全部任务和完成标准都满足时，才勾选 `doc/tasks/progress.md` 中对应模块。
- 主 Agent 同时更新 `progress.md` 的完成日期、实际验证命令和简短备注。
- 如果复核失败，恢复不成立的勾选项，并将精确失败交给对应子 Agent 修复。

### 5.4 集成职责

每个模块子 Agent完成后，主 Agent必须：

1. 检查其修改范围和依赖边界；
2. 运行该模块的核心测试和全局类型检查；
3. 确认没有跳过、禁用或弱化既有测试；
4. 检查没有秘密、真实凭据或无关功能进入仓库；
5. 检查模块接口与详细设计一致；
6. 更新总体进度后再解锁下游模块。

## 八、编码规则

1. 使用 TypeScript、Next.js App Router、React 和详细设计规定的技术栈。
2. 采用详细设计第 5 节目录和单向依赖规则。
3. 页面和业务组件不得直接调用 Sanity Client 或编写 GROQ。
4. Sanity 原始文档必须经过 Mapper 转换为领域契约。
5. UI 基础组件不得反向依赖业务模块。
6. 国际化、主题、弹窗和摄影加载状态彼此独立，不建立包揽全站的全局可变状态。
7. 初始内容服务端渲染；仅交互边界使用客户端组件。
8. 第三方 UI、图库和 Lightbox 通过本地适配层使用。
9. 图片必须有宽高和双语替代文本，缩略图不得默认请求高清原图。
10. 错误按模块隔离；单个区块失败不能无条件拖垮整页。
11. 禁止用 `any`、无说明的类型断言、空 catch 或吞错绕过类型与错误处理。
12. 不写依赖执行顺序、真实网络或当前日期才能通过的脆弱测试。
13. 保持依赖最少；新增依赖前确认现有依赖和平台能力无法合理解决。

## 九、完整测试要求

“完成代码”必须同时意味着“测试实际通过”。

### 9.1 每个模块必须具备

- 领域纯函数和状态机的单元测试；
- 正常输入、边界输入、无效输入和失败分支；
- 交互组件的用户行为测试，而不只检查内部实现；
- 外部服务适配器的契约或集成测试；
- 必要的键盘与可访问性测试；
- 由该模块引入的缺陷回归测试。

### 9.2 禁止的测试做法

- `skip`、`todo`、`only` 或注释掉失败测试；
- 只依赖快照而不验证行为；
- Mock 掉被测试模块的核心逻辑；
- 为通过测试而弱化断言；
- 将外部服务失败当成测试成功；
- 声称测试通过但未执行命令。

### 9.3 模块验收门槛

每个模块合并前至少运行：

```text
该模块单元/组件测试
受影响模块集成测试
TypeScript 类型检查
Lint
生产构建（当模块影响路由、构建或配置时）
```

### 9.4 全站最终门槛

M15 和 M16 完成前必须执行并通过：

- 全量单元测试；
- 全量组件与集成测试；
- TypeScript 类型检查；
- Lint；
- Next.js 生产构建；
- Playwright 桌面、平板和手机项目；
- 中文和英文关键旅程；
- 深色、浅色和系统主题旅程；
- axe 自动无障碍检查；
- 约 100 张测试照片的分页和性能检查；
- Sanity 发布到前台刷新测试；
- Vercel Preview 部署后冒烟测试。

如果某个检查失败，优先定位到负责模块并让对应子 Agent 修复。所有检查通过前不得宣告整体完成。

### 10.1 Sanity

- 使用环境中已有的非交互身份或 Token；不得要求浏览器人工登录。

- 自定义域名购买或绑定；
- ICP 备案；

- 付费带宽、存储或席位；

## 十一、秘密与环境变量

1. 真实值只写入本地忽略文件、进程环境或托管平台秘密存储。
2. `.env.example` 只列变量名称和说明。
3. 确认 `.gitignore` 覆盖本地秘密文件。
4. 不在测试 Fixture 中复制真实 Token。
5. 不在错误、截图、测试报告或最终回复中输出秘密。
6. 在最终检查中扫描仓库中的常见密钥模式和意外提交的环境文件。

## 十二、视觉、性能与可访问性不可退让项

- 开场动画所有路径均在 1000ms 内结束；
- `prefers-reduced-motion` 使用简化动画；
- 照片总量约 100 张时，首屏最多加载第一批，不一次加载全部；
- 摄影分类切换不会混入旧请求结果；
- 大图查看器支持缩放、键盘、触摸和焦点恢复；
- 科研弹窗支持焦点捕获、Esc、手机内部滚动；
- 深浅色均保持照片原始色彩；
- 三类设备功能完整，不创建手机删减版；
- 不接入访问统计、追踪 Cookie 或广告；
- 性能测试只在开发和 CI 中运行，不上传访客行为数据。
